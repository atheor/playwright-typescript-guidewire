# Test Data Management

## Philosophy

Test data in this framework follows two principles:

1. **Test data is code** — declared in builders/factories using TypeScript, not scattered across JSON fixtures or hardcoded strings.
2. **Tests own their data** — each test builds exactly the data it needs. No shared mutable state between tests.

---

## Domain Types

All test data objects are defined in `src/types/domain.types.ts`. Using strongly-typed domain objects means:
- Compiler catches typos and shape mismatches at build time
- IDE autocomplete guides test authors
- Refactoring field names propagates everywhere automatically

### Core domain model

```
Person                          Address
  firstName: string               line1: string
  lastName: string                line2?: string
  dateOfBirth: string (ISO)       city: string
  gender: Gender enum             state: string
  address: Address                postalCode: string
  phone: string                   country: string
  email: string

Policy                          Vehicle
  type: PolicyType enum           vin: string
  holder: Person | Company        year: number
  period: PolicyPeriod            make: string
  vehicles?: Vehicle[]            model: string
  drivers?: Driver[]              primaryUse: VehicleUse enum
  coverages?: Coverage[]

Claim                           BillingAccount
  policyNumber: string            policyNumber: string
  lossDate: string (ISO)          billingPlan: BillingPlan enum
  lossType: LossType enum         paymentInstrument: PaymentInstrument
  lossDescription: string
  claimant?: Claimant
  lossLocation?: Address
  estimatedAmount?: number
```

## Builder Pattern in Depth

### PolicyBuilder

```typescript
import { PolicyBuilder, VehicleBuilder, DriverBuilder } from '@builders/policy.builder';
import { PersonFactory } from '@builders/person.factory';

// Minimal — all defaults applied
const policy = new PolicyBuilder().build();

// Fully customized
const policy = new PolicyBuilder()
  .withType(PolicyType.CommercialAuto)
  .withHolder(PersonFactory.standard())
  .withPeriod('2026-06-01', '2027-06-01')     // custom effective/expiry dates
  .withVehicle(VehicleBuilder.highValue())
  .withVehicle(                                 // inline builder
    new VehicleBuilder()
      .withMake('Ford')
      .withModel('F-150')
      .withPrimaryUse(VehicleUse.Business)
      .build()
  )
  .withDriver(DriverBuilder.primaryDriver())
  .withCoverage({ type: 'BI', limit: 300000, deductible: 0 })
  .withCoverage({ type: 'COMP', deductible: 500 })
  .build();
```

**Defaults applied by `.build()` when no value is provided:**

| Field | Default |
|-------|---------|
| `type` | `PolicyType.PersonalAuto` |
| `holder` | `PersonFactory.standard()` |
| `period.effectiveDate` | Today's date |
| `period.expirationDate` | One year from today |
| `vehicles` | `undefined` (not set) |
| `drivers` | `undefined` (not set) |
| `coverages` | `undefined` (not set) |

### VehicleBuilder

```typescript
// Factory presets
VehicleBuilder.standard()    // recent Toyota Camry, Commute use
VehicleBuilder.highValue()   // current-year BMW M5, Pleasure use

// Custom
new VehicleBuilder()
  .withVin('1HGBH41JXMN109186')
  .withYear(2022)
  .withMake('Honda')
  .withModel('Civic')
  .withPrimaryUse(VehicleUse.Commute)
  .build();
```

**VIN default:** Generated by `@faker-js/faker` (`faker.vehicle.vin()`) — realistic format but not a real VIN.

### DriverBuilder

```typescript
// Factory preset
DriverBuilder.primaryDriver()   // insured relation, 10 years licensed

// Custom
new DriverBuilder()
  .withPerson(PersonFactory.youngDriver())
  .withRelation(DriverRelation.Child)
  .withLicenseState('CA')
  .withYearsLicensed(2)
  .build();
```

## PersonFactory in Depth

`PersonFactory` uses `@faker-js/faker` to generate realistic personal data. All locale-appropriate values are generated automatically.

```typescript
PersonFactory.standard()
// → { firstName: 'James', lastName: 'Rodriguez', dob: '1978-04-12',
//     gender: Gender.Male, address: { line1: '742 Evergreen Terrace', city: 'Springfield', ... } }

PersonFactory.youngDriver()
// → Same shape, dob in the 18–24 age range

PersonFactory.seniorDriver()
// → Same shape, dob in the 65–85 age range

PersonFactory.minimal()
// → Fixed values (no Faker), useful for deterministic tests
// → { firstName: 'Test', lastName: 'User', dob: '1980-01-01', phone: '555-555-5555', ... }

PersonFactory.usAddress(State.NY)
// → Generates a standalone US address for a specific state
```

## ClaimBuilder

```typescript
// Static presets for common claim scenarios
ClaimBuilder.autoCollision(policyNumber)
// → lossType: Auto, description: 'Vehicle collision...', estimatedAmount: 8500

ClaimBuilder.propertyDamage(policyNumber)
// → lossType: Property, description: 'Water damage...', estimatedAmount: 15000

// Custom
new ClaimBuilder()
  .withPolicyNumber('PC-00012345')
  .withLossType(LossType.Liability)
  .withLossDate('2026-03-15')
  .withLossDescription('Third-party slip and fall at premises')
  .withLossLocation(PersonFactory.usAddress(State.FL))
  .withEstimatedAmount(50000)
  .withClaimant({
    person: PersonFactory.standard(),
    relation: 'Third Party',
  })
  .build();
```

## BillingAccountBuilder and PaymentInstrumentFactory

```typescript
// Simple billing account
new BillingAccountBuilder()
  .withPolicyNumber('PC-00012345')
  .withBillingPlan(BillingPlan.Monthly)
  .withPaymentInstrument(PaymentInstrumentFactory.creditCard())
  .build();

// Payment instrument presets
PaymentInstrumentFactory.creditCard()
// → Visa test card number 4111111111111111 (Luhn-valid), expiry 12/28

PaymentInstrumentFactory.bankAccount()
// → Chase test routing number 021000021

PaymentInstrumentFactory.check()
// → Check with random reference number
```

## When to Use Builders vs. Factories

| Scenario | Use |
|----------|-----|
| Need specific field values for the test assertion | `new FooBuilder().withField(value).build()` |
| Test just needs a valid object and doesn't care about values | `FooFactory.standard()` |
| Setting up prerequisite data in `beforeAll` | `FooFactory.standard()` (fastest) |
| Exploring edge cases or boundary values | Custom builder chain |
| Multiple tests need the same shape with slight variations | Start from a factory then override with builder |

## Faker Seed for Deterministic Tests

When a test failure is hard to reproduce because Faker generated different data, seed it:

```typescript
import { faker } from '@faker-js/faker';

test.beforeEach(() => {
  faker.seed(12345); // same data on every run until you change the seed
});
```

Remove the seed once the bug is fixed to restore randomised coverage.
